# Synapse-V 신규 서비스 모니터링 온보딩 가이드

새로운 서비스(시스템)를 Synapse-V 통합 모니터링에 등록하는 전체 절차를 안내합니다.
계정 가입부터 시스템 등록, 서버 IP 연결, 수집 에이전트 설치, 알림 확인까지 순서대로 진행하면 됩니다.

## 전체 흐름 요약

```
① 계정 가입/승인  →  ② 담당자 등록  →  ③ 시스템 등록  →  ④ 서버 IP 연결
                                                              │
⑦ 모니터링 확인  ←  ⑥ 에이전트 설치  ←  ⑤ 담당자 연결  ←──────┘
```

| 단계 | 사용 메뉴 (사이드바) | 경로 |
|---|---|---|
| ① 계정 가입 | 로그인 화면 → 회원가입 | `/register` |
| ② 담당자 등록 | 관리 > **담당자 관리** | `/contacts` |
| ③ 시스템 등록 | 관리 > **시스템 관리** | `/systems` |
| ④ 서버 IP 연결 | 관리 > **시스템 관리** → 시스템 등록/수정 화면 내 "서버 IP" 패널 | `/systems` |
| ⑤ 담당자 연결 | 관리 > **시스템 관리** → 시스템 등록/수정 화면 내 "담당자" 패널 | `/systems` |
| ⑥ 에이전트 설치 | 관리 > **에이전트 관리** | `/agents` |
| ⑦ 모니터링 확인 | 운영 > **대시보드** / 알림 > **알림 이력** | `/dashboard`, `/alerts` |

---

## ① 계정 가입 및 승인

Synapse-V 프론트엔드(포트 3001)에 접속합니다.

1. 로그인 화면에서 **회원가입** (`/register`) 으로 이동
2. 이름 / 이메일 / 비밀번호(대문자+숫자 포함 12자 이상) 입력 후 가입
3. **관리자 승인 후 로그인 가능** — 가입 직후에는 로그인 시 "관리자 승인 대기 중인 계정입니다" 메시지가 표시됩니다
4. 관리자에게 승인 요청 → 관리자는 **내 프로필 > 사용자 관리** (`/admin/users`) 에서 계정을 승인(`is_approved`)합니다

> 권한(role)은 `admin` / `operator` 두 가지입니다. 시스템·에이전트 등록은 operator 권한으로 가능하며, 사용자 승인·LLM 설정 등은 admin 전용입니다.

## ② 담당자 등록 — 관리 > 담당자 관리 (`/contacts`)

시스템에 연결할 담당자를 먼저 등록합니다. 담당자는 장애 알림 Teams @mention 대상이자 LLM 분석 비용 청구 단위입니다.

1. **담당자 관리** 메뉴에서 담당자 추가
2. 입력 항목:
   - **사용자 선택** — ①에서 가입한 사용자를 이름/이메일로 검색하여 선택
   - **Teams UPN** — Teams @mention에 사용할 UPN (예: `user@company.com`)
   - **Webhook URL** — (선택) 담당자별 알림 채널이 필요한 경우

> 담당자별 LLM API 키(`llm_api_key`)가 등록되어 있으면 해당 키로 LLM 분석이 호출되어 **AI 비용이 담당자(팀)별로 분리 청구**됩니다. 미등록 시 전역 기본 키가 사용됩니다.

## ③ 시스템 등록 — 관리 > 시스템 관리 (`/systems`)

1. **시스템 관리** 메뉴 우측 상단의 **[시스템 등록]** 버튼 클릭
2. 입력 항목:

| 필드 | 필수 | 설명 |
|---|---|---|
| **시스템 ID (system_name)** | ✅ | 영문 소문자 식별자 (예: `my-system`). **등록 후 수정 불가** |
| **표시 이름** | ✅ | 화면에 노출되는 한글/영문 이름 (예: `고객경험 시스템`) |
| **상태** | | 활성/비활성 |
| **Teams Webhook URL** | | 이 시스템 전용 Teams 알림 채널. 미입력 시 전역 `TEAMS_WEBHOOK_URL` 로 폴백 |
| **설명** | | 시스템에 대한 간단한 설명 |

### ⚠️ system_name 규칙 (가장 중요)

`system_name`은 수집 에이전트가 Prometheus 메트릭에 붙이는 `system_name` 라벨과 **반드시 일치**해야 합니다.
불일치하면 메트릭·알림은 수신되지만 담당자 조회에 실패하여 **Teams 알림이 발송되지 않습니다.**

- 에이전트 관리 화면에서 시스템을 선택해 에이전트를 등록하면 라벨이 자동으로 일치되므로, 반드시 **시스템 등록 → 에이전트 등록** 순서를 지키세요.
- 서비스별로 Teams 채널·담당자·LLM 비용을 분리하려면 서비스마다 **별도 system_name으로 등록**합니다. 같은 팀이 여러 로그 파일만 수집하는 경우에는 하나의 시스템에 로그 소스를 여러 개 정의하면 됩니다 (⑥ 참고).

## ④ 서버 IP 연결

시스템 등록/수정 화면(드로어) 하단의 **"서버 IP" 패널**에서 이 시스템을 구성하는 물리 서버 IP를 연결합니다.

1. **[IP 추가]** 클릭
2. 입력 항목:
   - **서버 IP** (필수) — 예: `10.0.0.1`
   - **역할 구분** (선택) — 예: `WAS1`, `DB1` 등 서버 용도 라벨

서버가 여러 대(WAS 이중화, DB Primary/Standby 등)라면 IP를 각각 추가합니다.

## ⑤ 담당자 연결

같은 시스템 등록/수정 화면의 **"담당자" 패널**에서 ②에서 등록한 담당자를 연결합니다.

1. **[담당자 추가]** 클릭
2. 담당자 선택 + 역할 지정 후 **[연결]**

시스템↔담당자는 N:M 관계이므로 여러 담당자를 연결할 수 있습니다. 연결된 담당자가 장애 알림 Teams 카드의 @mention 대상이 됩니다.

## ⑥ 에이전트 설치 — 관리 > 에이전트 관리 (`/agents`)

대상 서버에 수집 에이전트를 설치합니다. 설치는 화면에서 SSH를 통해 원격으로 수행됩니다.

### 사전 요건 (대상 서버)

- Server A(Main Server)에서 대상 서버로 **SSH 접속 가능** (계정/비밀번호)
- 대상 서버에서 Server A의 Prometheus로 **Remote Write 가능** (네트워크 방화벽 오픈)
- RedHat/리눅스 x86_64 (synapse_agent는 musl 정적 바이너리)

### 설치 절차

1. **SSH 세션 등록** — 에이전트 관리 화면 상단에서 SSH 세션을 먼저 연결합니다
   - 호스트 IP / 포트(기본 22) / 계정명 / 비밀번호 입력
   - 비밀번호는 세션에만 사용되며 **DB에 저장되지 않습니다** (`agent_instances`에는 `ssh_username`만 저장)
2. **[에이전트 등록]** 클릭 후 입력:
   - **시스템** — ③에서 등록한 시스템 선택 (여기서 `system_name` 라벨이 결정됨)
   - **에이전트 타입**:

     | 타입 | 용도 |
     |---|---|
     | **Synapse 수집기** (`synapse_agent`) | 서버 메트릭 + 로그 에러 수집 (Rust 단일 바이너리) |
     | **DB 수집기** (`db`) | Oracle/PostgreSQL 등 DB 메트릭 수집 |
     | **OTel Java 수집기** (`otel_javaagent`) | JVM/WAS 트레이싱 (Tempo 연동) |

   - **호스트** — ④에서 연결한 서버 IP
   - **OS / 서버 역할** 선택
3. **Synapse 수집기 상세 설정** (타입이 `synapse_agent`인 경우):
   - **SSH 계정** — 설치·실행 계정 (예: `jeussic`)
   - **인스턴스 역할 (instance_role)** — HA 이중화 식별자. 이중화면 `was1`/`was2`, DB HA면 `db-primary`/`db-standby`, 단일 인스턴스면 비워두면 `default`
   - **수집항목** — 시스템 메트릭 / 로그 / 웹 서버 중 선택
   - **로그 수집 설정** — 로그 소스별로 추가:
     - 로그 경로 (여러 줄 입력 가능, glob 지원 — 예: `/server1/JeusServer.log`)
     - `log_type` — 로그 소스 구분 라벨 (예: `jeus`, `app`)
     - 키워드 — 에러 필터링 키워드 (예: `ERROR, CRITICAL`)
   - 한 에이전트에 로그 소스를 여러 개 정의하면 `config.toml`의 `[[log_monitor]]` 다중 섹션으로 배포됩니다
4. **설치 실행** — admin-api가 `config.toml`을 SFTP로 업로드하고 바이너리를 실행합니다. 설치 Job 진행 상태(pending → running → done/failed)는 화면의 설치 모니터에서 확인할 수 있습니다.

### 수집 동작 (참고)

- 에이전트는 로그를 키워드 매칭 → PII 마스킹 후 `log_error_total` Prometheus 메트릭으로 Remote Write합니다 (라벨: `system_name`, `instance_role`, `host`, `log_type`, `level`, `service_name`, `template`)
- 네트워크 단절 대비 WAL 버퍼 2시간 (`/var/lib/synapse-agent/wal`)

## ⑦ 모니터링 동작 확인

설치 완료 후 아래를 순서대로 확인합니다.

1. **에이전트 관리** (`/agents`) — 등록한 에이전트의 헬스 상태가 정상인지 확인
2. **대시보드** (`/dashboard`) — 신규 시스템 카드가 표시되고 메트릭이 수집되는지 확인
3. **로그 분석 확인** — log-analyzer가 5분 주기(`ANALYSIS_INTERVAL_SECONDS=300`)로 `log_error_total`을 조회해 LLM 분석을 수행합니다. 대상 서버 로그에 테스트 에러를 발생시켜 보고:
   - **알림 이력** (`/alerts`)에 `log_analysis` 알림이 쌓이는지
   - 시스템의 Teams 채널에 Adaptive Card 알림이 도착하고 담당자 @mention이 되는지
4. **인시던트** (`/incidents`) — 분석 결과가 인시던트로 생성되는지 확인

## 자주 발생하는 문제 (FAQ)

| 증상 | 원인 / 조치 |
|---|---|
| 메트릭은 수집되는데 Teams 알림이 안 옴 | `system_name` 불일치 가능성. DB `systems.system_name`과 에이전트 라벨이 일치하는지 확인. 시스템에 담당자가 연결되어 있는지도 확인 (⑤) |
| 알림이 엉뚱한 채널로 감 | Webhook 우선순위: 시스템별 `teams_webhook_url` → 전역 `TEAMS_WEBHOOK_URL`. 시스템 등록 화면에서 시스템별 URL 확인 |
| 이중화 서버 구분이 안 됨 | `instance_role`은 에이전트 타입이 아니라 **HA 인스턴스 식별자**. `was1`/`was2` 등으로 서로 다르게 지정 |
| 에이전트 설치 실패 | SSH 세션 계정과 에이전트 등록 시 SSH 계정 일치 여부, 대상 서버 → Server A Prometheus 방화벽 오픈 여부 확인. 설치 Job 이력(`agent_install_jobs`)의 실패 사유 참조 |
| 서비스별로 알림 채널을 나누고 싶음 | 서비스마다 별도 `system_name`으로 시스템을 분리 등록하고 에이전트 인스턴스도 분리 |
