# Agent-T Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** JDK 1.6~21 WAS 에 붙는 자체 트랜잭션 에이전트(Agent-T)와 수집 gateway(Go)·ClickHouse 저장소·신규 '트랜잭션' 화면을 만들고, 사용하지 않는 OTel/Tempo/n8n 을 걷어낸다.

**Architecture:** Agent-T 가 1초마다 액티브 스냅샷·완료 트랜잭션(요약+SQL 집계+선별 상세)을 gzip JSON 으로 gateway 에 보낸다. gateway 는 메모리 상태로 SSE 실시간을 내보내고, 1초 묶음으로 ClickHouse 에 적재하며, 5초 집계를 Prometheus remote write 로 기록한다. admin-api 는 ClickHouse 를 조회해 검색·상세 API 를, frontend 는 사용자 구성형 실시간 화면과 분석 화면을 제공한다.

**Tech Stack:** Java 6/8 바이트코드(ASM 소스 vendoring, 의존성 0), Go 1.26(gateway), ClickHouse 24.8, FastAPI/SQLAlchemy async(admin-api), React 18 + React Query 5 + ky + react-grid-layout(frontend), Docker Compose.

**Spec:** `docs/superpowers/specs/2026-10-29-agent-t-design.md` — 모든 태스크는 spec 을 함께 읽는다. 이 계획은 spec 의 P0~P2 범위만 다룬다(P3 제품별 계측·P4 분석 고도화·디스크 증설·방화벽 요청 제외).

## Global Constraints

- JDK 지원: legacy jar = JDK 1.6~1.7 (`-source 1.6 -target 1.6`, JDK 7 javac 로 컴파일), modern jar = JDK 8~21 (`--release 8`).
- 에이전트 런타임 의존성 0 — 외부 라이브러리는 소스 vendoring + 패키지 `com.synapsev.agentt.shaded.*` 로 이동.
- 에이전트 안전: 주입 코드 `try/catch(Throwable)` 무시, 클래스 필드·메서드 추가 금지(본문만 변경), `-Xbootclasspath/p` 금지, WAS 스레드는 전송을 절대 기다리지 않는다.
- 성능 예산: WAS CPU ≤ 3%, p95 +≤ 5ms, 힙 추가 ≤ 64MB.
- 느린 기준 기본 `3000`ms(`systems.tx_slow_threshold_ms`), 보관 기본 `7`일 범위 `1~30`(`systems.tx_retention_days`), `systems.environment` ∈ `dev|prod`.
- 상세 보존 조건: `elapsed_ms >= slow_ms` OR error OR `conn_leak>0` OR `conn_uncommit>0` OR 정상 샘플(`normal_detail_rate` 기본 `0.01`). JVM 당 상세 초당 상한 `50`.
- 전송 주기: 액티브·완료 배치 1초, JVM 지표 5초. gateway 집계 5초.
- 과부하 시 버림 순서: 상세 → SQL 집계 → 요약. 전송 버퍼 상한 8MB. gateway ClickHouse 대기열 상한 256MB.
- SQL 바인드 값 미수집. SQL 정규화 시 숫자·문자열 리터럴 → `?`. 사전 문자열 상한: SQL 8,192자, URI 1,024자(초과 시 잘라냄).
- 마스킹: IP `10.253.21.12` → `10.253.21.*`, 사용자 ID `abcdef` → `ab****` (2자 이하는 전부 `*`).
- 큐 구간: 정상 `< T`, 경고 `T ~ 3T`, 위험 `>= 3T` (T = 느린 기준).
- 명칭: `agent_type='agent_t'`, jar `agent-t.jar` / `agent-t-legacy.jar` / `agent-t-attacher.jar`, 컨테이너 `synapse-clickhouse` / `synapse-agent-t-gateway`, gateway 포트 `8330`, ClickHouse DB `agent_t`.
- 타임존: 저장·전송 UTC(epoch ms / naive UTC), 표출 KST(`formatKST`). Python 에서 `datetime.utcnow()`·`datetime.now()` 금지.
- PG 스키마: `models.py` + `configs/postgres/init.sql` + `configs/postgres/migrations/20261030_agent_t.sql` 3중 동기화, 감사 필드는 맨 끝.
- Python 은 `./venv/bin/python` 만 사용. async 엔드포인트에서 동기 I/O 금지(ClickHouse 는 `httpx.AsyncClient`).
- Frontend: 뉴모피즘 컴포넌트(`components/neumorphic/`)·CSS 변수만 사용, 하드코딩 색 금지. 큐·산점도는 Canvas.
- 클린룸: SysMaster·InterMAX 코드·클래스명·프로토콜 차용 금지.

## Review Focus

1. **JDK 7 에서 attach 로 이미 로딩된 서블릿·JDBC 클래스 재변환** — StackMapTable 오류가 나도 해당 클래스만 원본 유지되고 WAS 는 정상 응답해야 한다. → Task G2 `RetransformSafetyTest` + Task H1 JDK7 attach 시나리오.
2. **gateway 다운·지연 중 부하** — WAS p95 가 변하지 않고 에이전트 힙 사용이 8MB 버퍼 상한을 넘지 않아야 한다. → Task G1 `SenderOverflowTest` + Task H1 "gateway stop" 시나리오.
3. **한글 URI/SQL, 리터럴 포함 SQL, 64KB 짜리 SQL** — 정규화가 같은 ID 를 내고 잘림이 깨진 UTF-8 을 만들지 않아야 한다. → Task G1 `SqlNormalizerTest`, `UriNormalizerTest`.
4. **WAS 시계 오차(수 분)** — 산점도·검색 시각이 뒤섞이지 않고 만료일이 틀어지지 않아야 한다. gateway 가 배치 `ts` 와 수신 시각 차이로 인스턴스별 보정한다(차이 > 2s 일 때). → Task B1 `TestClockSkewCorrection`.
5. **느린 SSE 소비자(백그라운드 탭)·다수 시청자** — 수신·적재가 막히지 않아야 한다. 클라이언트별 버퍼 채널(256 이벤트), 가득 차면 그 클라이언트 이벤트만 버림. → Task B3 `TestSlowSubscriberDoesNotBlock`.
